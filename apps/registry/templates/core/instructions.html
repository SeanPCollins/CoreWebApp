Staff instructions

Use these tools to import chemical datasets, collect information from configured providers, and review structure findings. These steps are separate: importing a dataset creates source records and lookup work, while structure curation is where reviewed structures and supporting evidence are committed.

1. Import a dataset

  1. Open Import Data and upload a CSV or Excel file.
  2. Map the spreadsheet columns to their meaning, such as identifier, name, or structure, then continue to the staged preview.
  3. Review the staged rows and any identifier warnings. Confirm and queue the import when ready.
  4. Use the import status page to watch progress. It shows staged rows, imported rows, and any reported error. Large files are processed in the background.

A successful import retains the original input rows and creates or reuses searchable terms. It also queues compatible lookup jobs for active providers. It does not automatically add reviewed Structure records.

2. Gather information from providers

  1. Open Data Gathering and choose one or more active providers.
  2. Set Tasks per batch to control each chunk, and Maximum tasks to cap the total work for each selected provider. Leaving the cap blank allows all eligible work for the selected providers.
  3. Choose a run time and, if useful, schedule the run for later. Runs continue in the background and pause between batches.
  4. Monitor provider queues, active runs, recent results, and errors on the dashboard. Runs can be paused and resumed. A provider with an active run is skipped when scheduling another run.

Providers have different response times, access rules, and rate limits. Start with bounded runs and review results before increasing the cap. A rate-limit response may delay or pause a run. ChemSpider detail requests normally need at least 50 eligible IDs in a batch; its small-batch override may use additional API quota.

3. Review structure findings

  1. Open Structure Curation after provider findings are available.
  2. Start a random batch to work through a manageable saved sample, or use the full scan to process all currently pending findings. Unselected findings remain available for later batches.
  3. Review records flagged for missing or conflicting structure information. Expand the issue details to see the relevant reported values and evidence. Edit affected fields when appropriate.
  4. Accept records to commit their structures and evidence. Use Needs work for records to revisit in the saved batch. Reject removes a finding from that review queue but does not delete the underlying provider finding.

Accepted structures are committed to the database; leaving other records untouched does not accept or discard them. Multi-fragment records retain the full structure and non-trivial components. The current parent-generation policy uses the largest cleaned organic fragment as the parent.
